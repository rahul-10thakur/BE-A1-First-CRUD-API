# Task API â€” SQLite-backed CRUD

A Node.js + Express task-management API. This Week 3 update replaces in-memory storage with **SQLite** using `better-sqlite3`, while keeping the core CRUD endpoints and JSON response format.

## Features

- Persistent SQLite database (`tasks.db`) â€” tasks survive server restarts.
- Automatic database file and `tasks` table creation.
- Three starter tasks are inserted only when the table is empty.
- Parameterized SQL queries (`?`) for user-provided values.
- Full CRUD: create, read, update and delete tasks.
- Optional SQL-backed search and completion filters.
- Statistics endpoint, reset endpoint, health check and Swagger UI.

## Requirements

- Node.js 18 or newer (Node.js 20+ recommended)
- npm

## Getting started

```bash
git clone https://github.com/rahul-10thakur/BE-A1-First-CRUD-API.git
cd BE-A1-First-CRUD-API
npm install
npm start
```

The API runs at `http://localhost:3000`.

- Swagger UI: http://localhost:3000/docs
- Health check: http://localhost:3000/health
- Database: `tasks.db` in the project root (created automatically)

No separate database server or manual database setup is required. SQLite was chosen because it is a lightweight, serverless, zero-configuration database stored in a single file. It is suitable for this small CRUD project and preserves data between restarts.

## Database structure

The `tasks` table has these columns:

| Column | Type | Purpose |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | Unique task ID, generated by SQLite |
| `title` | TEXT NOT NULL | Task title |
| `done` | INTEGER NOT NULL DEFAULT 0 | Completion status (`0` = false, `1` = true) |

The database and table are initialized automatically when the app starts. The three example tasks are seeded only if the table contains zero rows, so restarting the server does not duplicate them.

## API endpoints

| Method | Endpoint | Description | Success |
|---|---|---|---|
| GET | `/tasks` | List all tasks | 200 |
| GET | `/tasks/:id` | Get one task | 200 |
| POST | `/tasks` | Create a task | 201 |
| PUT | `/tasks/:id` | Update title and/or done | 200 |
| DELETE | `/tasks/:id` | Delete a task | 204 |
| GET | `/stats` | Task counts | 200 |
| POST | `/reset` | Restore the three example tasks | 200 |
| GET | `/health` | Health check | 200 |

### Read tasks

```bash
curl -i http://localhost:3000/tasks
curl -i http://localhost:3000/tasks/1
```

Optional filters:

```bash
curl "http://localhost:3000/tasks?done=true"
curl "http://localhost:3000/tasks?done=false&search=book"
```

### Create a task

```bash
curl -i -X POST http://localhost:3000/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Buy milk"}'
```

A successful create returns `201 Created` and the new database-generated ID.

### Update a task

```bash
curl -i -X PUT http://localhost:3000/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"title":"Buy oat milk","done":true}'
```

You can send `title`, `done`, or both. The omitted field remains unchanged.

### Delete a task

```bash
curl -i -X DELETE http://localhost:3000/tasks/1
```

A successful delete returns `204 No Content` with an empty response body.

### Error responses

- `400 Bad Request` â€” missing/empty title, invalid `done`, or invalid query parameter.
- `404 Not Found` â€” task ID does not exist.

Example:

```json
{ "error": "Task 99 not found" }
```

## SQL example (Stage 4)

Open `tasks.db` in [DB Browser for SQLite](https://sqlitebrowser.org/), choose **Execute SQL**, and run:

```sql
SELECT * FROM tasks;
SELECT * FROM tasks WHERE done = 1;
SELECT COUNT(*) FROM tasks;
```

For example, `SELECT * FROM tasks WHERE done = 1;` returns only completed tasks. Changes made in DB Browser are visible through the API because both use the same `tasks.db` file.

## Proving persistence

1. Start the app using `npm start`.
2. Create a task using `POST /tasks`.
3. Stop the server (`Ctrl + C`).
4. Start it again using `npm start`.
5. Call `GET /tasks` â€” the created task is still present.

To verify a clean setup, stop the server and delete `tasks.db`. Start the app again; SQLite recreates the file, table and three seed tasks automatically.
